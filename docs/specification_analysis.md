# 專案概念規格深度分析與需求對照表

本文件作為本專案開發過程中的需求分析依據，嚴格依循根目錄之 `專案概念規格.md`，梳理核心理念、使用情境、第一版（V1）範圍及技術實現對應策略。

---

## 1. 核心理念與實作原則對照

| 規格核心原則 | 意義說明 | 第一版（V1）架構與實作對策 |
| :--- | :--- | :--- |
| **2.1 原始資料與個人認知必須分開** | 嚴格區分「原始資料（Records）」、「AI 整理內容（AI Organized）」、「個人認知（Thoughts）」與「知識整理（Topics）」 | • 資料結構分離：`Record`、`Thought`、`Topic` 獨立為頂層資料模型。<br>• 視覺區分：UI 提供不同色系、標籤與區塊，明確區別作者身分與內容性質。<br>• AI 生成欄位（`aiSummary`, `aiTags`, `aiSuggestedLinks`）標註「AI 產出」，不混入使用者正文。 |
| **2.2 保留來源與歷程** | 原始出處可追溯，AI 推論不可冒充使用者觀點，整理時不可悄悄覆蓋原始資料 | • 每筆想法可關聯一至多個來源，也可獨立存在。<br>• AI 整理內容採「建議（Suggestion）機制」，需經使用者點擊「採用/編輯」才轉化為確定內容。<br>• 想法記錄「類型（心得/疑問/反對/聯想/觀點演進）」與「建立/更新時間」，展現認知演進。 |
| **2.3 知識是網絡，不只是資料夾** | 多對多關係，非單一目錄樹；區分「AI 建議關聯」與「使用者確認關聯」 | • 關聯模型 `KnowledgeLink` 支援雙向關聯（Record ↔ Thought, Thought ↔ Thought, Record ↔ Topic, Thought ↔ Topic）。<br>• 關聯包含狀態 `status: 'confirmed' \| 'suggested'`。<br>• 提供視覺化知識圖譜（Graph View）與關聯導航面板。 |
| **2.4 降低紀錄負擔** | 快速保存，不必一次填滿欄位；個人想法不必強制依附來源；未閱讀資料不等於已理解 | • 快速新增 Modal 支援最少欄位輸入（僅輸入網址或一段文字即可立即保存）。<br>• 網址元資料解析提供失敗容錯（Graceful Fallback），失敗仍保留網址。<br>• 收件匣（Inbox）區分 `unread`（未讀/待處理）與 `processed`（已整理）。 |
| **2.5 AI 協助探索，不取代使用者判斷** | AI 角色為建議者與輔助者，任何重要變更由使用者決定 | • AI 分析功能提供建議按鈕，絕不自動覆寫已有欄位。<br>• 支援使用者自定義或即時觸發 AI 輔助分析（摘要、提取概念標籤、建議潛在連結與未解疑問）。 |

## 2. 第一版功能範圍（V1 Scope）落實對照

| 規格要求項目 | 具體功能規格 | 系統實作設計 |
| :--- | :--- | :--- |
| **首頁 Dashboard** | 近期紀錄、待處理資料、快速新增入口、知識探索概覽 | 儀表板整合：快捷新增卡片、未讀收件匣提醒、近期想法演進流、知識庫統計（資料量、主題數、關聯度）、快速跳轉。 |
| **快速新增 Quick Add** | 新增文字片段、網址、個人想法；流程輕量化 | 全站快捷鍵（或常駐新增按鈕），支援三合一新增面板（文字/網址/獨立想法），智慧偵測 URL。 |
| **收件匣 Inbox** | 集中檢視待閱讀、整理之項目，移出收件匣不失原身分 | 提供 `Inbox` 檢視模式，支援「標記已讀」、「轉換為想法」、「歸入主題」與「關聯現有紀錄」，狀態變更不影響唯一 ID 與資料完整性。 |
| **原始紀錄 Records** | 瀏覽、搜尋、檢視、編輯、刪除已保存來源 | 列表/卡片視圖切換，詳細資料抽屜/頁面。顯示原始文字、網址來源、AI 輔助摘要區、關聯的想法清單。 |
| **個人想法 Thoughts** | 獨立保存心得、疑問、反對意見、聯想與觀點演進 | 想法卡片獨立呈現，支援 5 種認知標籤類型（Insight, Question, Objection, Association, Perspective Shift），可手動掛載多來源。 |
| **主題與集合 Collections** | 多對多主題歸納、未解決問題追蹤 | 主題可聚合不同 Records 與 Thoughts；主題內設有「未解疑問清單」，落實規格第 3 節情境 5。 |
| **知識關聯 Links** | 手動建立、檢視來源/想法/主題關聯，區分 AI 建議 | 關聯管理面板，支援節點間連結與解除連結；內建互動式知識網絡圖（Network Graph），呈現知識脈絡。 |
| **搜尋與篩選 Search & Filter** | 全文檢索，多維度縮小範圍 | 即時搜尋引擎，支援依關鍵字、資料類型（網址/文字/想法/主題）、處理狀態（待處理/已處理）、標籤篩選。 |
| **資料管理 Data Management** | 匯出備份、還原復原、Obsidian 相容匯出 | 1. JSON 完整備份與還原（本地讀寫，無資料外洩風險）。<br>2. 一鍵匯出為 **Obsidian 相容 Markdown 壓縮包 (.zip)**，內建 YAML Frontmatter 與 `[[wikilinks]]`。 |
| **介面體驗 UI & Theme** | 現代專業知識管理風格，淺色/深色模式 | Tailwind 現代乾淨 UI，支援淺色（Light）與深色（Dark）主題即時切換，並自動持久化使用者偏好。 |

## 3. 非第一版範圍明確隔離

根據規格第 4.3 節，以下項目在 V1 中明確排除，避免過度工程：
1. **不依賴外部伺服器之複雜爬蟲**：採用前端容錯與選擇性 CORS 代理或直接本地快照保存。
2. **不建構重量級向量資料庫或複雜 RAG**：採用即時客戶端全文檢索與圖關聯演算法，保持輕量高效。
3. **不建立帳號與雲端多人協同系統**：以個人為核心，資料 100% 留存在本地瀏覽器（IndexedDB / localStorage），保障最高隱私與零伺服器成本。
4. **不依賴 Obsidian 外掛雙向同步**：透過結構化 Markdown 匯出機制，產出純標準之 Markdown + YAML + 雙向連結語法檔案包，天然與 Obsidian 100% 相容。
